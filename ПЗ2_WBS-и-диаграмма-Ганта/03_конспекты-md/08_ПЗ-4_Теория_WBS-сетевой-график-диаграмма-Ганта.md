## 1. Календарно-сетевое планирование
Составление календарного плана работ проекта: перечень работ, **их логические взаимосвязи**, исполнители и продолжительность; ресурсные, временные и внешние ограничения; на их основе — сроки выполнения.
Результат — подробный план, который **служит инструментом коммуникации, управления ожиданиями стейкхолдеров и основой отчётности об исполнении**.

## 2. WBS (ИСР, иерархическая структура работ)
- Иерархическая декомпозиция проекта на управляемые компоненты, задачи и работы; задаёт иерархию и зависимости.
- Шаги: идентификация основных компонентов → подзадачи → иерархия → зависимости → уровни управления.
- Декомпозиция: проект → подпроекты → пакеты работ разных уровней → детальные работы. **Декомпозиция** — деление результатов на меньшие управляемые компоненты до уровня **пакетов работ**.
- WBS определяет **всё содержание** проекта. Работы вне WBS не являются работами проекта.

### Правила размера пакетов работ
1. **8/80** — от 8 до 80 чел.-ч (1–10 рабочих дней).
2. **Отчётного периода** — не длиннее интервала между совещаниями по ходу проекта.
3. **Полезности** — дробить, только если так легче оценить, распределить и проконтролировать.

### Ориентиры при создании WBS
- Для каждого элемента сформулирован измеримый результат.
- Результат вышестоящего элемента агрегирует результаты «дочерних».
- Пакеты и операции уникальны.
- Структура полная, но не избыточная.
- Верхние уровни совместимы с оргструктурой проекта.
- Нижние элементы достаточно крупны для управления, но не избыточны для контроля.

### Этапы разработки WBS
1. **Определение конечных результатов** — изучить концепцию, устав, бизнес-план.
2. **Выбор критериев разбиения** — продуктовый, функциональный или организационный; последовательность декомпозиции.
3. **Основные пакеты работ** — результаты, необходимые для создания продукта, но не являющиеся его целями.
4. **Степень детализации** — соответствует внутренней системе управления и контроля; контроль не должен становиться самоцелью.
5. **Анализ и усовершенствование** — пока все участники не будут удовлетворены результатами.

### Подходы к созданию WBS (пример — «Платформа онлайн-обучения»)

| Подход | Уровень 1 |
|---|---|
| **а) Продуктовый** (по конечным модулям) | Модуль управления курсами · Личный кабинет студента · Система тестирования и сертификации |
| **б) По жизненному циклу** (по этапам создания) | Анализ требований и проектирование архитектуры · Разработка и модульное тестирование · Развёртывание, интеграционное тестирование и релиз |
| **в) Функциональный** (по специализациям) | Работы UX/UI-дизайнеров · Работы разработчиков (фронтенд + бэкенд) · Работы инженеров по автоматизации тестирования |
| **г) Организационный** (по территориям или подразделениям) | Команда разработки (Санкт-Петербург) · Команда поддержки инфраструктуры (Новосибирск) · Внешний подрядчик по кибербезопасности |

### Промт для генерации WBS (из презентации)
```text
Ты — эксперт по управлению проектами (PMI, PMBOK).

- Ключевые стейкхолдеры: [заказчик, инвесторы, конечные пользователи]

ТРЕБОВАНИЯ К СТРУКТУРЕ WBS:

ПРАВИЛА:

- Не включай ресурсы, сроки и ответственных — только структуру работ.
- Учитывай специфику IT: интеграции, тестирование, безопасность, обучение.
- Если нужны особые этапы (миграция данных, импорт контента) — добавь.
```

## 3. Календарный план
- Работы связаны **зависимостями** (Dependences), которые задают порядок выполнения.
- Все работы объединяются в **график работ** (Schedule).
- **Критические работы** (Critical Tasks) — те, задержка которых сдвигает срок проекта.
- Критические работы образуют **критический путь** (Critical Path); его длительность равна длительности проекта.

### Типы зависимостей
- **финиш — старт (FS)** — самый распространённый;
- **финиш — финиш (FF)**;
- **старт — старт (SS)**;
- **старт — финиш (SF)**.

### Виды операций
Операциями последования связываются работы самого нижнего уровня ИСР.
1. **Операция слияния** — у неё больше одной непосредственно предшествующей операции (A → C, B → C).
2. **Параллельные операции** — могут выполняться одновременно, потому что не зависят друг от друга (но не обязаны).
3. **Дробящаяся операция** — за ней сразу следуют несколько операций (A → B, A → C).

**Для каждой операции определяют:** предшествующие (что должно быть завершено непосредственно перед ней), следующие (что идёт сразу за ней) и параллельные (что может идти одновременно).

### Оценка длительности операций

| Тип оценки | Применяется | Требует |
|---|---|---|
| **Экспертная** | Высокая сложность оценки, много влияющих факторов | Исторической информации, опытных экспертов, рекомендаций |
| **По аналогам** | Мало детальной информации, ранние фазы | Фактической длительности прошлых работ, экспертной оценки, схожести работ |
| **Параметрическая** | Есть нужная информация | Нормативов производительности, объёмов работ, данных о ресурсах |
| **Анализ резервов** | Есть риски, способные увеличить длительность | Экспертов по содержанию работ и рискам |

## 4. Сетевые графики
**Сетевой график** — графическое изображение технологической последовательности операций с длительностями и всеми временными параметрами.
1. **Операции в узлах (ОУ)** — метод предшествования, **PDM**. Используется чаще.
2. **Операции на стрелках (ОС)** — метод стрелочных диаграмм, **ADM**.

**Диаграмма предшествования** — операции показаны прямоугольниками, зависимости — стрелками (Старт → A → B → Финиш; Старт → C → F, G → Финиш).

### Пример: сеть проекта «Бизнес-центр»

| Операция | Описание | Предшествующие | Время, раб. дн. |
|---|---|---|---|
| A | Утверждение приложения | — | 5 |
| B | Планы конструирования | A | 15 |
| C | Изучение трафика | A | 10 |
| D | Проверка наличия службы | A | 5 |
| E | Отчёт персонала | B, C | 15 |
| F | Утверждение (одобрение) на комиссии | B, C, D | 10 |
| G | Ожидание работ | F | 170 |
| H | Включение в работу | E, G | 35 |

**Расчёт (прямой и обратный проход, выполнен по данным слайдов):**

| Оп. | ES | EF | LS | LF | Резерв TS | Критическая |
|---|---|---|---|---|---|---|
| A | 0 | 5 | 0 | 5 | 0 | да |
| B | 5 | 20 | 5 | 20 | 0 | да |
| C | 5 | 15 | 10 | 20 | 5 | |
| D | 5 | 10 | 15 | 20 | 10 | |
| E | 20 | 35 | 185 | 200 | 165 | |
| F | 20 | 30 | 20 | 30 | 0 | да |
| G | 30 | 200 | 30 | 200 | 0 | да |
| H | 200 | 235 | 200 | 235 | 0 | да |

**Критический путь: A → B → F → G → H = 235 рабочих дней.**

## 5. Метод PERT
- **t_m** — наиболее вероятная (с учётом ресурсов, производительности, доступности, зависимостей);
- **t_o** — оптимистичная (самый благоприятный сценарий);
- **t_p** — пессимистичная (самый неблагоприятный сценарий).

**Длительность = (t_o + 4·t_m + t_p) / 6**

## 6. Оценка сроков начала и окончания работ
Узел сети: `ES | ID | EF` / `TS | Описание` / `LS | Dur | LF`; стрелка между узлами i → j — опережение или задержка d_ij.

| Обозначение | Смысл |
|---|---|
| ID | код операции |
| Dur | длительность |
| **ES** | ранний старт — самая ранняя дата начала, когда все предшественники завершены; ES = max(EF предшественников) |
| **EF** | ранний финиш = ES + Dur |
| **LS** | поздний старт = LF − Dur |
| **LF** | поздний финиш — самая поздняя дата окончания без задержки проекта; LF = min(LS последователей) |
| **TS** (Total slack) | резерв = LS − ES = LF − EF; на критическом пути равен 0 |
| i, j | предыдущее и последующее событие |

**Прямой проход** (ранние сроки) отвечает на вопросы: как скоро может начаться операция (ES), закончиться (EF), завершиться весь проект (TE)?
**Обратный проход** (поздние сроки): самые поздние LF и LS, какие операции образуют критический путь (CP), на сколько можно задержать операцию (TS)?

## 7. Диаграмма Ганта
- Состоит из полос вдоль оси времени (горизонтальная ось).
- Каждая полоса — отдельная задача: концы — начало и завершение, длина — длительность.
- Вертикальная ось — перечень задач.
