# Тема 1. Введение в управление проектами

*Источник: `УП тема 1 2024 (5).pptx` — Кашникова И.В., БГУИР*

## 1. Понятие проекта

Определения проекта по разным стандартам:

- **PMI (США):** проект — временное предприятие, предназначенное для создания уникальных продуктов, услуг или результатов.
- **IPMA (международная):** проект — целенаправленная деятельность временного характера, предназначенная для создания уникального продукта или услуги.
- **Английская ассоциация проект-менеджеров:** проект — отдельное предприятие с определёнными целями, часто включающее требования по времени, стоимости и качеству результатов.
- **Всемирный банк ("Оперативное руководство" №2.20):** проект — комплекс взаимосвязанных мероприятий, предназначенных для достижения, в течение заданного периода времени и при установленном бюджете, поставленных задач с чётко определёнными целями.

**Рабочее определение:** проект — это комплекс усилий, предпринимаемых с целью получения конкретных уникальных результатов в рамках отведённого времени и в пределах утверждённого бюджета, выделяемого на оплату используемых/потребляемых ресурсов.

### Признаки проекта (обобщённо)
- Уникальность целей и деятельности
- Ограниченная во времени деятельность (определённое начало и конец)
- Направленность на достижение конкретных целей
- Координированное выполнение взаимосвязанных действий
- Последовательная разработка и уточнение целей/планов (прогрессирующая детализация)

Границы проекта визуализируются согласно PMBOK (см. слайд-схему в оригинале — область между содержанием, сроками, бюджетом и качеством).

## 2. Управление проектом

**Управление проектом** — управленческая деятельность, направленная на достижение целей проекта с требуемым качеством, в рамках бюджета, в установленные сроки, при существующих ограничениях и неопределённости. Предполагает:
- создание временной динамичной организационной структуры;
- привлечение необходимых ресурсов и технологий;
- применение управленческих знаний, опыта, методов и инструментов.

Три равнозначные формулировки сути управления проектом:
1. Приложение знаний, навыков, инструментов и методов к работам проекта для удовлетворения предъявляемых требований.
2. Создание временной динамичной организационной структуры для выполнения работ, привлечения ресурсов/технологий и применения управленческих компетенций.
3. Управленческая деятельность, направленная на достижение результатов в условиях заданных параметров (срок, бюджет, ресурсы и др.).

## 3. Эволюция управления проектами

| Период | Событие |
|---|---|
| 1910 | Генри Гант создал столбчатые диаграммы (диаграммы Ганта) для визуализации сроков и последовательности задач |
| 1937 | Лютер Гулик разработал матричную структуру управления (двойное подчинение: руководитель проекта ставит задачи, функциональный руководитель определяет способ их выполнения) |
| 1953–1954 | ВВС США совместно с Комитетом по спецпроектам по вооружению собрали воедино знания по управлению проектами |
| 1956 | Создание метода критического пути (CPM) |
| 1956–1958 | ВМС США изобрели технологию PERT (анализ сроков и ресурсов) |
| 1959 | Под влиянием NASA распространилось понятие "жизненный цикл проекта" |
| 1977 | Появление методов управления конфликтами в проектах |
| 1977–1979 | Созданы различные структуры организации проектов |
| 1987 | PMI опубликовала первую редакцию PMBOK; управление проектами становится отдельной дисциплиной |
| 1991 | В Германии выходит один из самых полных учебников по управлению проектами |

**Укрупнённые этапы развития:**
- 1900–1958 — трансформация проектного менеджмента, начало развития методологии;
- 1958–1979 — распространение инструментов проектного менеджмента;
- 1980–1994 — применение ИТ в проектном менеджменте;
- в настоящее время — управление проектами признанная методология деятельности во всех развитых странах.

**Дальнейшие направления развития:** развитие управления рисками проекта; совершенствование методов командообразования; развитие ИТ в области проектного управления; разработка новых стандартов; формирование национальных и международных программ сертификации.

**Инициирование проектов обычно вызвано:** требованиями рынка, нуждами организации, требованиями заказчика, технологическим прогрессом, требованиями законодательства.

## 4. Классификация программных продуктов

1. По типу функциональности: системное ПО, бизнес-приложения.
2. По способу распространения: коммерческое, проприетарное, для разработки, бесплатное, свободное/открытое ПО.
3. По специализации: научные и инженерные приложения, образовательное ПО, медиа-приложения, прикладное ПО.
4. По платформе: для настольных компьютеров, мобильных устройств, веб-браузеров.
5. По уровню доступа к исходному коду: коммерческое / проприетарное / свободное / открытое.

## 5. Особенности ИТ-проектов

ИТ-проекты — одни из самых сложных: высокие риски (технологические и внедренческие/человеческий фактор), высокий процент незавершённых или сорванных по срокам/бюджету проектов. По Дж. Филипсу, менеджер ИТ-проекта должен обладать качествами режиссёра (работа со "звёздами"), тренера спортивной команды (руководство командой ради приза) и командира космического корабля (знать всё о происходящем на борту).

**Отличительные особенности ИТ-проектов:**
- сложность оценки эффективности — трудно точно измерить результаты и влияние;
- высокий уровень риска — неопределённости могут привести к значительным проблемам;
- широкая огласка ошибок — просчёты становятся известны большой аудитории;
- значительные бюджеты;
- специфичное разделение ролей — чёткое разграничение между заказчиком и исполнителем.

## 6. Закон 4P и проектный менеджмент

### Концепция 1. Цели проекта определяют его содержание
- **Цель** — описание того, что мы хотим достичь.
- **Стратегия** — каким образом мы собираемся эти цели достигать.
- Проекты преобразуют стратегии в действия, а цели — в реальность.

### Критерии SMART (кратко; подробнее — отдельный конспект "SMART-цели")
SMART-цели делятся на четыре стандартные группы:
- **Предметные цели / качество** — точно сформулированное задание и признаки качества, которые должны быть достигнуты;
- **Цели по срокам** — временные рамки успешного завершения проекта;
- **Цели по расходам** — реализация не должна превышать заданные расходы;
- **Особые цели**.

### Концепция 2. Тройственное ограничение
Три основных ограничения: **сроки, затраты, качество**.
- Закон Лермана: «Любую техническую проблему можно преодолеть, имея достаточно времени и денег».
- Следствие Лермана: «Вам никогда не будет хватать либо времени, либо денег».

Приоритет между сроками/расходами/содержанием индивидуален для каждого проекта и может меняться по ходу работы; чаще всего на первом месте — предметные цели. Важно, чтобы каждый участник проекта знал приоритеты.

### Концепция 3. Учёт неопределённости
Уникальность целей и деятельности проекта — источник неопределённости: менеджер не может абсолютно точно определить состав работ, предвидеть все условия реализации, точно сформулировать требования к ресурсам. Важно найти баланс между ограничениями и неопределённостью.

**Неопределённость** — неполнота и неточность информации о внутренних и внешних условиях реализации проекта, из-за чего возможны непредсказуемые события с неизвестными вероятностными характеристиками. Усиление динамики и сложности деятельности предприятия + изменения внешней среды → рост неопределённости → возможны потери прибыли/выручки/имущества → это характеризует категория **риска**.

### Концепция 4. Концепция жизненного цикла проекта
**Жизненный цикл проекта** — последовательность фаз проекта, задаваемая исходя из потребностей управления проектом. ЖЦ делится на фазы, фазы — на стадии, стадии — на этапы.
Традиционное разбиение на 4 крупных этапа: **формулирование проекта, планирование, осуществление, завершение**.

### Концепция 5. Концепция временной организационной структуры
- Привлечение исполнителей к выполнению проекта;
- чёткое распределение ответственности за достижение целей;
- ключевая роль менеджера проекта;
- необходимость вписаться в существующую структуру организации, реализующей проект.

### Концепция 6. Интеграция технологических и управленческих компетенций
Наличие технологий и квалифицированных исполнителей — главные составляющие успеха проекта.

## 7. Стандарты управления проектами

**Стандарты управления проектами** — документы, определяющие понятия, термины, методологии, фазы, роли, обязанности и компетентность в сфере проектного менеджмента; представляют собой совокупность знаний и опыта, проверенных практически и признанных авторитетными источниками.

### PMBOK (Project Management Body of Knowledge)
Разработан Project Management Institute (PMI), один из самых распространённых стандартов. Определяет процессы, практики и знания для эффективного управления проектами; включает управление областями знаний проекта, процессы управления и соответствующие входы/выходы/инструменты.

Структура руководства PMBOK включает разделы:
- Введение
- Процессы управления проектами
- Области знаний управления проектами
- Роль проектного менеджера
- Каркас управления проектами

**9 областей знаний PMBOK:**
1. Управление интеграцией проекта
2. Управление содержанием проекта
3. Управление сроками проекта
4. Управление стоимостью проекта
5. Управление качеством проекта
6. Управление человеческими ресурсами проекта
7. Управление взаимодействием (коммуникациями) в проекте
8. Управление рисками проекта
9. Управление контрактами (закупками) проекта

### PRINCE2 (Projects in Controlled Environments)
Методология, разработанная в Великобритании. Предоставляет набор описаний ролей, процессов и шаблонов для управления проектами разной сложности. Выделяет **шесть основных переменных проекта**: время, стоимость, качество, объём работы, риски и выгоды.

**Основные принципы PRINCE2:**
- непрерывная обоснованность бизнес-цели;
- роли и ответственности;
- управление по стадиям;
- управление по исключениям;
- фокус на продуктах;
- принцип «адаптировать к контексту».

**Процессы PRINCE2:**
- Запуск
- Инициирование
- Направление
- Управление этапом
- Управление поставками
- Управление этапами (границами стадий)
- Завершение проекта

### ISO 21500
Международный стандарт, разработанный ISO. Даёт руководство по управлению проектами: общие принципы, процессы и практики; является общим руководством и может быть адаптирован к разным организационным контекстам.
Ключевые элементы стандарта: контекст проекта, руководящие принципы, управление рисками, процессы управления проектом, роли и ответственности.

## 8. Истории о «безумных идеях» (кейсы из практики)

Иллюстративные мини-кейсы про реальных разработчиков/предпринимателей-энтузиастов (переписавших системы, компиляторы, почтовые клиенты и т.д. в одиночку/на энтузиазме) и про компании (одну "консервативную", "гигантскую"; и одну, основанную двумя людьми, бросившими колледж, с офисом в спальне и сборкой в гараже) — использовались как разминочные примеры на лекции, иллюстрирующие непредсказуемость успеха ИТ-проектов и разнообразие организационных культур.
