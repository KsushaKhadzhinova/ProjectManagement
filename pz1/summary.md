# Что и как делали в ПЗ1 (кратко)

**Задание:** разработать концепцию проекта — обосновать проект (Business Case, 5W), определить границы (MoSCoW), ограничения, декомпозировать цель на задачи, проанализировать стейкхолдеров.

**Что сделали:**
1. Взяли за основу реальный проект **NotaCode** (веб-IDE для диаграмм на собственном DSL) вместо абстрактного учебного примера — это позволило использовать уже существующие бизнес-документы проекта (`docs/business/`, `docs/planning/agile-plan.md`) как источник данных.
2. Собрали 5W и таблицу «Проблемы → Решения» из готовой концепции продукта.
3. Синтезировали одну итоговую SMART-фразу цели проекта (MVP до 06.12.2026, 100 % покрытие тестами) из уже существующего разбора SMART-целей продукта.
4. Перенесли и проверили правило MoSCoW «Must ≤ 60 %» (получили 44 % — правило выполняется без переноса пунктов).
5. Заполнили таблицу технических/правовых/организационных/временных/бюджетных/пользовательских ограничений на основе реального стека и условий проекта (один разработчик + AI-агенты как Review Board).
6. Развернули 13 продуктовых эпиков (E0–E13) в дерево из 25 конкретных задач в хронологическом порядке.
7. Взяли готовый реестр из 17 стейкхолдеров проекта и построили для него матрицу «влияние/интерес» (диаграмма на Python/matplotlib) и распределение по 4 квадрантам A/B/C/D со стратегиями работы.

**Инструменты:** Python (matplotlib) — построение диаграммы матрицы стейкхолдеров; Excel + VBA (`risk-map.xlsx`, `modRiskMap.bas`) — заполнение реестра рисков и автоподпись точек карты рисков (дополнительный практический материал по теме «риски», используется в связке с ПЗ1 как часть бизнес-анализа).

**Результат:** полностью заполненный отчёт [report.md](report.md) / [report.docx](report.docx), готовый к оформлению по СТП БГУИР и защите.
