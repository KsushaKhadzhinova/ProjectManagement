# Что и как выполнено в ПЗ1 (кратко)

**Задание:** разработка концепции проекта — обоснование проекта (Business Case, 5W), определение границ (MoSCoW), ограничений, декомпозиция цели на задачи, анализ стейкхолдеров.

**Ход выполнения:**
1. За основу взят реальный проект **NotaCode** (веб-IDE для диаграмм на собственном DSL) вместо абстрактного учебного примера — это позволяет использовать уже существующие бизнес-документы проекта (`docs/business/`, `docs/planning/agile-plan.md`) как источник данных.
2. 5W и таблица «Проблемы → Решения» собраны из готовой концепции продукта.
3. Итоговая SMART-фраза цели проекта (MVP до 06.12.2026, 100 % покрытие тестами) синтезирована из существующего разбора SMART-целей продукта.
4. Правило MoSCoW «Must ≤ 60 %» перенесено и проверено (получено 44 % — правило выполняется без переноса пунктов).
5. Таблица технических/правовых/организационных/временных/бюджетных/пользовательских ограничений заполнена на основе реального стека и условий проекта (один разработчик, AI-агенты в роли Review Board).
6. 13 продуктовых эпиков (E0–E13) развёрнуты в дерево из 25 конкретных задач в хронологическом порядке.
7. Готовый реестр из 17 стейкхолдеров проекта использован для построения матрицы «влияние/интерес» (диаграмма на Python/matplotlib) и распределения по 4 квадрантам A/B/C/D со стратегиями работы.

**Инструменты:** Python (matplotlib) — для построения диаграммы матрицы стейкхолдеров; Excel + VBA (`risk-map/risk-map.xlsm`, `modRiskMap.bas`) — для заполнения реестра рисков и автоподписи точек карты рисков (дополнительный практический материал по теме «риски», связанный с ПЗ1 как часть бизнес-анализа).

**Результат:** отчёт [report.md](report.md) / [report.docx](report.docx) заполнен полностью, готов к оформлению по СТП БГУИР и к защите.
