## Подробно

### Подготовка (общая для всех ПЗ)
1. **Разбор 11 файлов курса** (5 лекций/презентаций, 2 справочника, шаблон ПЗ1, 2 Excel-шаблона, презентация ПЗ-4).
   - Текст извлекался из XML внутри .pptx/.docx/.xlsx, включая SmartArt и заметки к слайдам.
   - Старый .ppt конвертировали в .pptx через PowerPoint.
   - Слайды-картинки (схемы, диаграммы) экспортировали в PNG и прочитали.
   - На основе этого написано 11 md-конспектов (`03_конспекты-md/` в каждой лабе).
2. **Изучение проектов.**
   - `E:\NotaCode` — документация нового продукта: концепция, SMART, стейкхолдеры, BRD, архитектура, agile-план.
   - `E:\VisualDSL-Platform` — прототип DiagramCode: код, ветки, реестр рисков, аудит дефектов.
   - Решение: объект всех ПЗ — **NotaCode**. DiagramCode — источник требований и рисков.
3. **Структура репозитория:** по папке на ПЗ, каждая лаба — в своей ветке GitHub; старые работы по DiagramCode — в `archive/`.

### ПЗ1. Концепция проекта
**Как делали:**
1. Данные из `E:\NotaCode\docs` (concept, smart-goals, stakeholders, agile-plan, BRD, architecture) свели в тексты разделов.
2. Скрипт `tools/build_pz1_notacode.py` заполнил **оригинальный шаблон преподавателя** через python-docx: таблицы, списки, удаление подсказок, вставка рисунка WBS из Graphviz.
3. Скрипт `04_расчёты-python/concept_charts.py`:
   - посчитал долю Must (8 / 23 = 34,8 % ≤ 60 %) и число задач (22 в диапазоне 15–25);
   - определил квадранты стейкхолдеров A–D по правилам шаблона;
   - нарисовал матрицу стейкхолдеров, MoSCoW и WBS-дерево.
4. Итоговый текст продублирован в `ОТЧЁТ.md`.

**Результаты:** `07_результаты/ПЗ1 - Концепция проекта - NotaCode - Хаджинова.docx`, 3 схемы в `06_схемы/`.

### ПЗ2. WBS, сетевой график, Гант
**Как делали:**
1. WBS ПЗ1 (22 задачи) укрупнили до **14 работ в 6 этапах** — задание требует 12–15.
2. **PERT:** для каждой работы экспертно заданы O / M / P в месяцах (неделя = 0,25 мес.); T = (O + 4M + P) / 6 даёт 0,25 / 0,5 / 0,75 мес.
3. **Зависимости FS:** требования → архитектура → фундамент → [сервер: DSL → валидация; Gateway → Workspace] ‖ [клиент: макеты → IDE → холст] → экспорт → тесты → сдача.
4. **CPM** (`cpm_notacode.py`): прямой и обратный проход, резервы, критический путь, даты, σ проекта. Этот же алгоритм проверен на трёх примерах методички: 56 дн., 18 мес., 235 дн. — совпадает.
5. **Схемы:** WBS и сетевой график PDM (Graphviz, узлы ES | ID | EF / TS / LS | D | LF), Гант (matplotlib, критический путь красный, резервы штрихованы).
6. **Excel:**
   - `tools/build_pz2_notacode.py` заполнил оригинальный планировщик формулами CPM (openpyxl);
   - затем файл **открыт в самом Excel через COM**: формулы пересчитаны, значения ES/EF/LS/LF/TS сверены с Python, картинка листа «Планировщик» экспортирована как скриншот.
7. **VBA-макрос `PZ2_RunAll`** делает то же внутри Excel: лист WBS с формулами PERT, «ТАБЛИЦА ДАННЫХ», период планировщика и отдельный лист «Гант NotaCode» с датами.
8. Отчёт .docx собран скриптом (оформление по шаблону).

**Результаты:** критический путь 1.0 → 2.0 → 4.0 → 5.0 → 10.0 → 11.0 → 13.0 → 14.0, **2,75 мес. (21.09–06.12.2026)**, резервы 0,25–0,75 мес. у 3.0, 6.0–9.0 и 12.0.

### ПЗ3. Управление рисками
**Как делали:**
1. **Идентификация** по четырём источникам:
   - контрольный лист Боэма;
   - допущения ПЗ1;
   - критический путь ПЗ2;
   - аудит дефектов прототипа (`legacy-audit.md`: XSS в SVG, ключ LLM в бандле, три синтаксиса DSL).
2. 13 рисков шести категорий, у каждого последствие, триггер, P и I (0–1), стратегия и меры, привязка к пункту Боэма.
3. `tools/build_pz3.py` заполнил **оригинальный Excel-шаблон**: Таблица1, формула H, диаграмма с подписями R1–R13. Отчёт .docx собран тем же скриптом.
4. Файл открыт в Excel через COM: H пересчитан, экспортированы картинки таблицы и карты.
5. `risk_analysis.py`: реестр md/csv, ранжирование, карта с зонами порогов, тепловая матрица 5 × 5, Парето, стратегии, **Монте-Карло** (в среднем ≈ 4,9 наступивших риска, P90 = 7).
6. **VBA-макрос `PZ3_RunAll`:** заполняет таблицу, добавляет приоритет и стратегию, подсвечивает H (пороги в ячейках, не зависит от языка Excel), перестраивает карту, создаёт листы «Ранжирование» и «Тепловая матрица».

**Результаты:** высокий — R1 (0,56), средний — 11, низкий — R13 (0,12); стратегии: снижение 6, уклонение 4, принятие 2, передача 1.

### Оформление отчётов по СТП 01–2017 БГУИР
1. По тексту СТП (разд. 2, прил. Л, Н) написан класс `tools/stp_report.py`, который задаёт правила оформления:
   - А4, поля 30/15/20/20 мм, Times New Roman 14, интервал 1,0, абзацный отступ 1,25 см;
   - номер страницы внизу справа, на титуле без номера;
   - разделы с новой страницы, заголовки полужирные;
   - «Рисунок 2.1 – …» по центру с пробельными строками, «Таблица 2.1 – …» слева;
   - формулы с номером (2.1) справа;
   - перечисления через «–»;
   - ссылки [n], список источников по ГОСТ 7.1, приложения «ПРИЛОЖЕНИЕ А (обязательное)».
2. `tools/build_stp_reports.py` собирает три отчёта. Структура: титульный лист → содержание → 1 Цель работы → 2 Ход работы (подразделы) → Выводы → Список использованных источников → приложения (листинги VBA и Python в ПЗ2 и ПЗ3).
3. `tools/word_finalize.ps1` открывает отчёт в Word:
   - разбивает таблицы на стыке страниц и ставит «Продолжение таблицы N» с повтором шапки;
   - обновляет содержание и номера страниц;
   - сохраняет PDF.
4. PDF отрисованы в картинки и просмотрены постранично. Объём отчётов: ПЗ1 — 15 с., ПЗ2 — 23 с., ПЗ3 — 17 с.
