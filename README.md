# Управление проектами — практические задания (гр. 60121)

Курс «Управление проектами» (БГУИР, преподаватель И.В. Кашникова), LMS `courses.bsuir.by`, курс id=180 («Управление проектами (Кашникова)»). Все три практических задания ниже выполнены на основе реального проекта **DiagramCode** (репозиторий `E:\VisualDSL-Platform` на этой машине — только для чтения, изменять его нельзя; полное описание проекта — там же, `README.md` и `AI_CONTEXT.md`).

## Структура репозитория

```
materials/           — присланные преподавателем исходники (теория + шаблоны), без изменений
├── theory/          — лекционные .ppt/.pptx/.doc/.docx
└── templates/       — пустые шаблоны для заполнения (шаблон ПЗ1, Excel-планировщик, Excel-карта рисков)
pz1-concept/         — ПЗ1: Концепция проекта (Business Case), заполненный отчёт
pz-wbs-gantt/        — WBS-диаграмма + график Ганта (CPM)
risk-management/     — карта рисков и реестр рисков
google-sheets/       — готовые к импорту в Google Таблицы файлы (.tsv) + скрипт, который их генерирует
tools/               — скрипты, которыми собраны все Word-отчёты и страница-разбор (можно пересобрать в любой момент)
```

**Начни с файла [`ЧТО ОСТАЛОСЬ СДЕЛАТЬ ТЕБЕ.md`](ЧТО%20ОСТАЛОСЬ%20СДЕЛАТЬ%20ТЕБЕ.md)** — там пошагово всё,
что нужно сделать самой (импорт в Google Таблицы, скриншоты, вставка в отчёты, загрузка на LMS).
Почему всё сделано именно так — в [`ЧТО И ПОЧЕМУ БЫЛО СДЕЛАНО.md`](ЧТО%20И%20ПОЧЕМУ%20БЫЛО%20СДЕЛАНО.md).

## Google Таблицы

Готовая таблица со всеми расчётами и диаграммами: «DiagramCode - расчеты (Управление проектами)»,
https://docs.google.com/spreadsheets/d/1VN2x7adTeLzvm9_SByaPJ015bFYzFBySs87lYVX9HsM/edit — листы
«WBS-Гант DiagramCode», «WBS-Гант Пример 1», «Риски». Её строит скрипт Google Apps Script, привязанный к
таблице: он загружает `google-sheets/setup_sheets.js` из этого репозитория и создаёт данные, формулы,
условное форматирование, полосовую диаграмму Ганта и точечную карту рисков. `setup_sheets.js` генерируется
тем же `generate_tsv.py` из шаблона `setup_sheets.template.js`. Скриншоты из таблицы лежат в
`pz-wbs-gantt/Google Таблицы - *.png` и вставлены в отчёт ПЗ2.

Excel на машине нет, поэтому все расчёты дополнительно подготовлены для Google Таблиц. В папке
`google-sheets/` три файла (`.tsv`, разделитель — табуляция), которые импортируются через **Файл → Импорт**
с опцией «Преобразовать текст в числа, даты и формулы». Они генерируются скриптом `generate_tsv.py` из тех же
данных, что и `verify_cpm.py` / `verify_cpm_example1.py` и Excel-файл рисков, поэтому числа совпадают
с уже проверенными. Формулы в сгенерированных файлах дополнительно вычислены отдельным интерпретатором
и сверены с результатом CPM по каждой из 12 работ обоих вариантов.

- `1 - WBS-Гант - DiagramCode.tsv` — таблица CPM + текстовый график Ганта по дням + итог (38 дней) и проверка
- `2 - WBS-Гант - Пример 1 (методичка).tsv` — то же для примера методички (56 дней)
- `3 - Риски - DiagramCode.tsv` — реестр 9 рисков, коэффициент, приоритет по порогам шаблона, место в рейтинге

## Важное открытие про названия файлов (не доверяй именам вслепую)

Файл `УП-ПЗ1-60121.pptx` называется «ПЗ1», но по содержимому — это **теория** к WBS/Гант-практическому (первый слайд буквально подписан «Пз-4»). Настоящий шаблон для **ПЗ1 (Концепция проекта)** — это `шаблон пз1 -УП- 26.docx`: 6 разделов (Business Case/5W, SMART-цель, MoSCoW, ограничения, декомпозиция задач, анализ стейкхолдеров). Свериться с реальным текстом задания на LMS перед тем, как доверять названиям файлов.

**Подтверждено владелицей репозитория:** файл «Концепция 2026 для 60121» на LMS — это и есть `шаблон пз1 -УП- 26.docx` (тот же файл, просто по-разному подписан в разных местах). Заполнение `pz1-concept/*.docx` опирается именно на его структуру + материалы `Что такое SMART.docx` и `Кто такие стейкхолдеры.docx` — актуальному заданию соответствует.

## Статус трёх заданий (на 2026-09-17)

### 1. ПЗ1 — Концепция проекта (`pz1-concept/`)
Официальный шаблон `шаблон пз1 -УП- 26.docx` заполнен целиком (все 6 разделов), предмет — DiagramCode. SMART-цель, MoSCoW, ограничения, декомпозиция на 4 этапа/12 работ (переиспользует WBS из `pz-wbs-gantt/`), матрица стейкхолдеров (Ксения, руководитель, конечный пользователь, AI-провайдер, хостинг-провайдеры, фоновые ИИ-агенты). Плюс отдельный отчёт `Отчёт - ПЗ1 - Концепция проекта.docx` в её обычном университетском формате (см. выше) — краткое связное изложение того же материала, ссылается на заполненный шаблон как на приложение.

### 2. WBS + график Ганта (`pz-wbs-gantt/`)
**Важно:** задание на LMS буквально просит «выполнить пример 1» (готовый учебный кейс «Обучение сотрудников кибербезопасности», 12 работ) в файле-планировщике. Поэтому здесь готовы **два варианта** — выбор, какой сдавать, зависит от того, проверяет ли преподаватель буквальное совпадение с примером методички:

**Вариант А — реальные данные по DiagramCode** (WBS/CPM для курсового среза, Волна 1) — 4 этапа, 12 работ, критический путь 1→2→4→6→8→10→11→12, общая длительность 38 дней.
- `WBS-диаграмма-DiagramCode.png` / `.dot` — иерархическая WBS-диаграмма (Graphviz).
- `Планировщик проекта - DiagramCode.xlsx` — заполненная «ТАБЛИЦА ДАННЫХ».
- `verify_cpm.py` — независимая проверка расчёта в Python, без Excel.

**Вариант Б — буквально «Пример 1» из методички** (обучение сотрудников кибербезопасности, 12 работ, 4 этапа: Подготовка / Настройка платформы / Разработка контента и обучение / Контроль и внедрение) — критический путь 1→2→3→6→8→9→10→11→12, общая длительность 56 дней.
- `WBS-диаграмма-Пример1.png` / `wbs_example1.dot` — иерархическая WBS-диаграмма того же примера.
- `Планировщик проекта - Пример 1 (методичка).xlsx` — та же «ТАБЛИЦА ДАННЫХ», но заполненная данными прямо из листа «Пример 1» исходного шаблона.
- `verify_cpm_example1.py` — независимая проверка расчёта в Python для этого варианта.

Оба варианта используют один и тот же Excel-шаблон и одну и ту же логику CPM (формулы ES/EF/LS/LF/резерв/критический путь пересчитываются в Excel автоматически, лист «Планировщик проекта» рисует график Ганта по условному форматированию без дополнительных действий) — отличаются только исходные данные. Если для сдачи нужен только один — сдать вариант Б (буквальное совпадение с заданием) safer по умолчанию, а вариант А оставить как более содержательную демонстрацию реального проекта, если преподаватель это оценит. Отчёт `Отчёт - ПЗ2 - WBS и график Ганта.docx` описывает вариант А подробно и упоминает вариант Б как альтернативу.

### 3. Карта рисков (`risk-management/`)
Явного скриншота-задания для этой практической не было (только теория + общий шаблон с сайта course-excel.ru, в котором изначально лежал чужой пример про биометрический доступ в офис — он удалён). Заполнен реестр из 9 рисков DiagramCode в структурную таблицу `Таблица1` листа «Таблица с рисками» (лист «Карта рисков» содержит встроенную scatter-диаграмму, которая берёт данные из столбцов F/G этой же таблицы — она обновится автоматически при открытии в Excel). Отчёт `Отчёт - ПЗ3 - Управление рисками проекта.docx` разбирает теорию (PMBOK, стратегии реагирования) и сам реестр.

## Как это соотносится с VisualDSL-Platform

Этот репозиторий **не изменяет** `E:\VisualDSL-Platform` — только использует его как источник контента (архитектура, риски, пробелы вроде нереализованных `uml.class`/`idef0`, состояние веток) для трёх заданий выше. Если состояние DiagramCode изменится (например, ветки смёржены, или нотации доделаны) — соответствующие места в `pz1-concept/*.docx` и `risk-management/*.xlsx` могут устареть и потребовать сверки.
