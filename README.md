# Управление проектами

Материалы и практические задания по дисциплине «Управление проектами» (БГУИР).

Выполненные работы включают:
- Анализ теоретического материала по темам курса
- Выполнение практических заданий ПЗ1 и ПЗ4  
- Создание и настройка Excel-инструментов для управления рисками и планирования проектов
- Интеграция всех компонентов в единую систему управления проектами на примере личного проекта NotaCode

## Что было сделано в ПЗ1 «Разработка концепции проекта»

В рамках ПЗ1 были выполнены следующие разделы:
- Анализ ситуации по методологии 5W (что, кто, когда, где, почему)
- Формулировка SMART-цели проекта с проверкой по всем пяти критериям
- Таблица «Проблемы → Решения» с минимум 6 практическими примерами
- Перечень ограничений проекта по шести категориям (технические, правовые, организационные, временные, бюджетные, пользовательские)
- Декомпозиция проекта на 25 управленческих задач в иерархическом порядке
- Реестр заинтересованных сторон с анализом их влияния и интереса
- Выводы и рекомендации, подкреплённые конкретными данными расчётов

Файлы ПЗ1:
- `plan.md` — детальный план выполнения работы с этапами и сроками
- `instructions.md` — пошаговое руководство с формулами, примерами данных и скриншотами
- `report.md` / `report.docx` — основной отчёт, оформленный в соответствии со СТП БГУИР
- `checklist.md` — промежуточный чек-лист для самопроверки
- `summary.md` — концентрат проделанной работы и полученных результатов
- `risk-map.xlsm` + `modRiskMap.bas` — рабочая копия Excel-инструмента с автоматизацией
- `img/` — сгенерированные диаграммы матрицы стейкхолдеров и карты рисков

## Что было сделано в ПЗ4 «Диаграмма Ганта и сетевое планирование»

В рамках ПЗ4 были реализованы:
- Структурная декомпозиция проекта (WBS) из 15-20 работ с уникальной нумерацией
- Расчёт времени выполнения работ методами экспертной оценки и PERT
- Построение таблицы предшественников для всех работ
- Критический путьmethod (CPM) — определение длительности проекта и критических работ
- Построение диаграммы Ганта на основе расчётных дат начала и окончания
- Построение сетевого графика методом предшествования (PDM)
- Валидация результатов через cross-check между Excel и Python реализациями

Файлы ПЗ4:
- `plan.md` — план работ с этапами и контрольными точками
- `instructions.md` — детальная инструкция по выполнению расчётов
- `report.md` / `report.docx` — отчёт с пояснениямиmethodology и результатами
- `checklist.md` — чек-лист промежуточной проверки
- `summary.md` — ключевые findings и выводы
- `gantt-planner.xlsm` + `modGanttCriticalPath.bas` — рабочий инструмент с автоматизацией
- `calc_and_charts.py` — универсальный Python-скрипт для расчётов и визуализации
- `img/` — сгенерированные диаграммы Ганта (с выделением критического пути) и сетевые графики
- `cpm_table.csv` — таблица промежуточных расчётов ES/EF/LS/LF/резерв

## Инструменты управления проектами

### Excel-инструмент «Карта рисков»

Предназначен для:
- Ведения реестра проектных рисков с оценкой вероятности и воздействия
- Автоматического расчёта приоритета рисков (вероятность × воздействие)
- Визуализации риск-карты с цветовой индикацией приоритетов
- Генерации комментариев к рискам для отчётности

Ключевые файлы:
- `risk-map/risk-map.xlsm` — рабочая книга с листами реестра и визуализации
- `risk-map/modRiskMap.bas` — VBA-макрос для автоматизации заполнения и подписи

### Excel-инструмент «Планировщик проекта»

Предназначен для:
- Ввода исходных данных по работам (названия, длительности, зависимости)
- Автоматического расчёта сроков работ (early start, early finish, late start, late finish)
- Вычисления временных резервов и определения критического пути
- Построения визуальной диаграммы Ганта

Ключевые файлы:
- `gantt-planner/gantt-planner.xlsm` — рабочая книга с данными и формулами
- `gantt-planner/modGanttCriticalPath.bas` — VBA-макрос для расчётов и визуализации
- `pz4/calc_and_charts.py` — альтернативная реализация на Python для проверки результатов

## Проверка перед сдачей

Перед финальной подачей работ рекомендуется:
1. Указать актуальные ФИО и номер группы на титульном листе отчёта (`report.docx`)
2. Выполнить само-проверку по чек-листу в папке задания (`pz*/checklist.md`)
3. Пройти сводный чек-лист всех заданий (`CHECKLIST-1-ALL-TASKS.md`)
4. Проверить соответствие исходным требованиям (`CHECKLIST-2-SOURCE-REQUIREMENTS.md`)
5. Убедиться, что все файлы находятся в соответствующих папках репозитория
6. Выполнить тестовый запуск макросов для подтверждения их работоспособности

## Структура веток в репозитории

Репозиторий организован по принципу feature branching:
- `master` — основная ветка с teoretical материалами, шаблонами заданий и служебными файлами
- `feature/pz1` — рабочая ветка для выполнения ПЗ1 (слита в master после завершения)
- `feature/pz4` — рабочая ветка для выполнения ПЗ4 (слита в master после завершения)

Каждая feature ветка содержит только файлы, относящиеся к конкретному заданию, что облегчаетreview и интеграцию результатов.

## Пример использования на реальном проекте

Все материалы и инструменты апробированы на личном проекте NotaCode — веб-среде для создания диаграмм на собственном предметно-ориентированном языке (DSL). Проект включает поддержку нотаций: UML, BPMN, ERD, IDEF0/1X/3, DFD, сети Петри.

Это позволило:
- Протестировать инструменты управления рисками на реальном проекте с техническими неопределённостями
- Валидировать методы сетевого планирования на итеративном процессе разработки
- Демонстрировать практическую применимость teoretical положений курса
- Создать связь между academic упражнениями и real-world разработкой

## Технические требования

Для полного использования материалов необходимо:
- Microsoft Excel 2016 или новее (для работы с .xlsm файлами и VBA-макросами)
- Python 3.8+ (для запуска проверочных скриптов, опционально)
- Доступ к редактированию макросов в Excel (необходимо включить доверие к VBA проекту)
