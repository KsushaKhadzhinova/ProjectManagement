# Инструкция по ПЗ1: что и как делать

## 1. Что сдаём
Один файл Word — заполненный шаблон `02_задание-оригиналы/Шаблон ПЗ1 - Концепция проекта (шаблон пз1 -УП- 26).docx`.
Готовый вариант: `07_результаты/ПЗ1 - Концепция проекта - NotaCode - Хаджинова.docx`. Текст с пояснениями — `ОТЧЁТ.md`.

## 2. Два способа выполнения

### Способ А — автоматически (5 минут)
```bash
cd E:\ИИТ\УправлениеПроектами
python tools/build_pz1_notacode.py
python ПЗ1_Концепция-проекта/04_расчёты-python/concept_charts.py
```
Первый скрипт заполняет шаблон через python-docx и вставляет рисунок WBS (Graphviz). Второй рисует матрицу стейкхолдеров, MoSCoW и WBS для отчёта.
Нужны: Python 3.11+, `pip install python-docx matplotlib`, Graphviz (`dot` в PATH).

### Способ Б — вручную в Word
1. Скопируйте шаблон, переименуйте: `ПЗ1 - Концепция проекта - NotaCode - <Фамилия>.docx`.
2. Титул: «Слушатель гр. 60121 … <И.О. Фамилия>», «По практическому занятию № 1».
3. Заполняйте раздел за разделом, копируя текст из `ОТЧЁТ.md`.
4. Раздел 4: после таблицы 4.1 вставьте иерархический список и рисунок `06_схемы/WBS декомпозиции цели - NotaCode.png`.
   Подпись: «Рисунок 1 – Иерархическая структура работ проекта NotaCode».
5. Раздел 5.2: при желании вставьте `06_схемы/Матрица стейкхолдеров - NotaCode.png` («Рисунок 2 – Матрица стейкхолдеров»).
6. Удалите все подсказки в угловых скобках `<...>` и курсивные примеры шаблона.

## 3. Какие рисунки и схемы нужны

| Рисунок | Обязателен? | Файл | Как сделать |
|---|---|---|---|
| Иерархическая структура работ (дерево) | **Да** (раздел 4: «схема (дерево) или иерархический список») | `06_схемы/WBS декомпозиции цели - NotaCode.png` | `concept_charts.py` (Graphviz) или вручную в draw.io / Visio |
| Матрица стейкхолдеров (влияние × интерес) | Желательно | `06_схемы/Матрица стейкхолдеров - NotaCode.png` | `concept_charts.py` |
| Диаграмма MoSCoW | По желанию (наглядно подтверждает Must ≤ 60 %) | `06_схемы/MoSCoW - NotaCode.png` | `concept_charts.py` |

Скриншоты в ПЗ1 не нужны: это текстовая работа.

## 4. Расчёты и формулы
- **Доля Must:** Must / (Must + Should + Could + Won't) × 100 % = 8 / 23 × 100 % = **34,8 %**. Правило: ≤ 60 %.
- **Число задач WBS:** 4 + 3 + 5 + 4 + 3 + 3 = **22**. Норма: 15–25.
- **Квадрант стейкхолдера** (по шаблону):
  - влияние 4–5 и интерес 3–5 → **A**;
  - влияние 1–3 и интерес 3–5 → **B**;
  - влияние 1–3 и интерес 1–2 → **C**;
  - влияние 4–5 и интерес 1–2 → **D**.

## 6. Типичные ошибки
- SMART без числа или без даты — критерии M и T не выполнены.
- Must > 60 % — перенесите часть требований в Should.
- Задачи вида «Сделать сайт» — формулируйте конкретно: «Сверстать оболочку IDE».
- Стейкхолдеры без оценок 1–5 или без квадранта.
- Даты в разделах расходятся: MVP везде 13.12.2026, защита — 18.12.2026.
