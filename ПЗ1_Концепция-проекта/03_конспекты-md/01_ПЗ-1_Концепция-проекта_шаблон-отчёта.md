## РАЗДЕЛ 1. Обоснование проекта (Business Case)

### 1.1. Ключевые вопросы (модель 5W)

| Элемент | Ключевые вопросы | Ваш ответ |
|---|---|---|
| WHAT? | Что делаем? Какую проблему решаем? | |

| Критерий | Ваш ответ |

## РАЗДЕЛ 2. Содержание и границы проекта (Scope)

### 2.1. MoSCoW-приоритизация требований

| Приоритет | Расшифровка | Требования проекта |
|---|---|---|
| **Must have** | Без этого система не имеет смысла. Сделать обязательно | 1. … 2. … 3. … |
| **Should have** | Важно, но можно отложить на второй релиз | 1. … 2. … |
| **Could have** | Хорошо бы, если останутся ресурсы | 1. … 2. … |
| **Won't have** | Сознательно не делаем в этом проекте | 1. … 2. … |

> **Правило:** Must have — не более **60 %** общего списка.

### 2.2. Исключения (что НЕ входит в проект)
3–5 пунктов того, что заказчик мог бы ошибочно считать частью проекта: «НЕ входит: …».

## РАЗДЕЛ 3. Ограничения проекта

| Категория | Конкретные ограничения |
|---|---|
| Технические | язык, БД, платформа, совместимость, интернет |
| Правовые / законодательные | законы, стандарты, персональные данные, лицензии |
| Организационные | доступ к экспертам, согласования, режим работы |
| Временные | сроки: старт, MVP, релиз, финал |
| Бюджетные | общая сумма, резерв, что включено и что нет |
| Пользовательские | что умеют пользователи, нужно ли обучение |

## РАЗДЕЛ 4. Задачи разработки (декомпозиция цели)
Логика: SMART-цель разбивается на конкретные шаги.

| № | Элемент | Что писать |
|---|---|---|
| 4.1 | Декомпозиция задач | 5–7 конкретных шагов к цели (например: 1. Собрать требования, 2. Разработать макеты, 3. Написать код, 4. Протестировать, 5. Внедрить) |

Для каждого этапа — **3–5 конкретных задач**.

**Правила:**
- этапы идут в хронологическом порядке (анализ → проектирование → разработка…);
- задачи конкретны: не «Сделать сайт», а «Сверстать главную страницу»;
- всего **15–25 задач**.

**Оформление:** схема (дерево) или иерархический список.

## РАЗДЕЛ 5. Анализ стейкхолдеров
**Задание:** определите всех, кто влияет на проект или зависит от него. Оцените влияние и интерес по шкале **1–5**, распределите по квадрантам и выберите стратегию.

### 5.1. Идентификация

| № | Стейкхолдер | Тип (внутренний / внешний) | Почему важен |
|---|---|---|---|
| 1–5 | | | |

### 5.2. Матрица стейкхолдеров
**Влияние** — способность повлиять на проект (1–5). **Интерес** — насколько важен результат (1–5).

| Влияние \ Интерес | Низкий (1–2) | Высокий (3–5) |
|---|---|---|
| **Высокое (4–5)** | **D: минимальное информирование** — по ключевым вехам, без деталей | **A: активное вовлечение** — регулярные отчёты, согласование решений, личные встречи |
| **Низкое (1–3)** | **C: минимальный контроль** — мониторинг, общие дайджесты | **B: консультирование** — учитывать мнение, привлекать к обсуждениям |

### 5.3. Распределение по квадрантам

| Квадрант | Стратегия | Стейкхолдеры |
|---|---|---|
| A (высокое влияние / высокий интерес) | Активное вовлечение | |
| B (низкое влияние / высокий интерес) | Консультирование | |
| C (низкое влияние / низкий интерес) | Минимальный контроль | |
| D (высокое влияние / низкий интерес) | Минимальное информирование | |
