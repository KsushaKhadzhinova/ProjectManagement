## Раздел 1. Обоснование проекта (Business Case)

### 1.1. Модель 5W

| Элемент | Ответ |
|---|---|
| **WHAT?** | NotaCode — веб-IDE (PWA) класса «diagram as code». Диаграмма описывается кодом на собственном DSL, код проверяется по правилам нотации и отображается на холсте; диаграммы хранятся, версионируются и экспортируются, AI-ассистент генерирует и исправляет код. **Проблема:** формальные нотации (IDEF0, IDEF1X, IDEF3, DFD, ERD, UML) строятся вручную в графических редакторах, а текстовые инструменты (PlantUML, Mermaid, D2) не проверяют правила методологических нотаций. |
| **WHO?** | Студенты технических специальностей, системные и бизнес-аналитики, архитекторы ПО. Заказчик — автор проекта (Product Owner). Результат принимают руководитель курсовой по ИТиВП (ч. 2) и преподаватель УП. |
| **WHY?** | На рынке нет инструмента с единым DSL для инженерных и методологических нотаций, валидацией по стандартам и git-подобной историей. Сроки задаёт учебный план: курсовая и ЛР ч. 2 выполняются в осеннем семестре 2026 г. на компонентах продукта. |
| **WHEN?** | Старт — 21.09.2026. MVP — 13.12.2026 (спринт S11). Защита — 18.12.2026 (плановая дата, уточняется). Post-MVP (BPMN, сети Петри) — после защиты. |
| **WHERE?** | Chrome, Edge, Firefox актуальных версий на настольных ПК; установка как PWA с офлайн-черновиками; облачный хостинг (Netlify, Render/Fly.io, Neon). |

### 1.2. Бизнес-окружение
Проект одновременно является курсовой работой по ИТиВП (ч. 2), объектом ЛР этой дисциплины и продуктом с перспективой версии Pro. Рынок делится на два класса:
- текстовые DSL для инженерных нотаций — PlantUML, Mermaid, D2, Structurizr;
- графические редакторы — draw.io, Ramus, BPwin, где методологические нотации строятся вручную.

Бесплатные LLM API и бесплатные облачные тарифы позволяют реализовать AI-функции и развёртывание без бюджета. MVP нужен к защите в декабре 2026.

| № | Проблема (как есть) | Решение (что сделает продукт) |
|---|---|---|
| 1 | IDEF0, IDEF1X, IDEF3, DFD рисуют вручную; соответствие стандарту не проверяется; большая диаграмма правится долго | DSL и профили нотаций с валидацией: ошибки с номером строки и колонки, автоисправление типовых ошибок |
| 2 | PlantUML, Mermaid и D2 не поддерживают методологические нотации; на каждую нотацию свой синтаксис | Единый язык и каталог «нотация → тип → уровень»: UML, ERD, IDEF0/1X/3, DFD в MVP; BPMN и сети Петри в Post-MVP |
| 3 | Нет построчной истории, diff и отката; писать код с нуля нужно, зная синтаксис | Неизменяемые коммиты (SHA-256-блобы), diff и откат; шаблоны, документация и AI-ассистент (4 режима) |

### 1.3. SMART-цель

| Критерий | Ответ |
|---|---|
| **S** | MVP NotaCode: Web IDE (React, Monaco, SVG-холст), Edge Gateway (Node.js, Express), Language Service (Python, Lark) с нотациями волны 1 (UML, ERD, IDEF0, IDEF1X, IDEF3, DFD), сохранение на устройство и в БД, экспорт SVG/PNG, AI-ассистент в режиме заглушки |
| **M** | Шаблон каждой из 6 нотаций проходит Run без ошибок; анализ ≤ 300 мс для 200 узлов; покрытие тестами 100 %; Lighthouse ≥ 90; сквозной сценарий «код → Run → сохранение → экспорт» без ошибок |
| **A** | Требования и архитектура (C4, ADR) готовы в S0; 13 недельных спринтов; сервисы подключаются поэтапно (walking skeleton → Language → Workspace); только бесплатные сервисы. План ПЗ2 даёт 11 недель по критическому пути |
| **R** | Устраняет проблемы 1–3 и даёт материал для курсовой и ЛР ч. 2 (Gateway закрывает требования ЛР1–ЛР8) |
| **T** | MVP — до 13.12.2026; защита — 18.12.2026 |

> **Итоговая SMART-цель:** до 13.12.2026 разработать и продемонстрировать MVP веб-IDE NotaCode с валидацией и рендером 6 нотаций волны 1, сохранением, экспортом SVG/PNG и AI-заглушкой при покрытии тестами 100 % и оценке Lighthouse не ниже 90.

### 1.4. Правила приёмки
1. Для каждой нотации волны 1 код встроенного шаблона проходит Run без ошибок, диаграмма отображается на холсте.
2. Ошибки DSL выводятся в панели Problems, маркерами редактора и тостами Error/Warning/OK с номером строки и колонки.
3. Сохранение на устройство и в БД, экспорт в SVG и PNG работают без ошибок; кросс-подсветка «элемент ↔ строки кода» работает в обе стороны.
4. CI проходит: покрытие 100 % (строки, ветви, функции), линтеры без замечаний.
5. Lighthouse ≥ 90 во всех категориях; пояснительная записка (20–30 с.) принята руководителем.

### 1.5. Допущения

| № | Допущение | Влияние, если не сбудется |
|---|---|---|
| 1 | Преподаватель ИТиВП согласует Python-сервисы (FastAPI) наряду с Node.js/Express | Перенос Language и Workspace на Node.js, MVP сдвигается на 2–3 спринта |
| 2 | Бесплатные тарифы Netlify, Render/Fly.io, Neon, CloudAMQP, Upstash сохранятся до защиты | Смена хостинга, риск недоступности демо-стенда |
| 3 | Защита назначена не ранее 18.12.2026 | Объём MVP сокращается, Should have уходит в Post-MVP |
| 4 | Бесплатные ключи LLM API (Gemini, Groq, OpenRouter) остаются доступны | AI-ассистент показывается только как заглушка |
| 5 | Каждая ЛР ч. 2 укладывается в один недельный спринт | ЛР вытесняют продуктовые задачи, MVP сдвигается |
